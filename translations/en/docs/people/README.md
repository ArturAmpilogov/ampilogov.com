# People and Profiles

## Why a Hybrid Is Needed

One huge list is convenient for an overview but poorly suited to evidence. A separate profile for every chance mention would create hundreds of almost empty files. That is why three levels are used:

1. `people/index-1800-1999.md` — a general list of all confirmed people;
2. `people/profiles/` — separate profiles only for people with several documents, variant names or a disputed identification;
3. `records/` — cards for the primary documents on which all facts are based.

## Person Identifiers

Each person is assigned a stable code `P####`. The code does not encode a date, place or surname: this information may be refined, while the identifier must stay the same.

A new person appears in the register only after at least one confirmed `R####` card with a photocopy has been added.

## When to Create a Separate Profile

A profile is created if:

- there are two or more documents;
- the surname or first name is recorded in different forms;
- there are people with the same name who must be distinguished;
- spouses, children or parents are named in documents;
- the person takes part in a proved migration route.

For a single mention, a line in the general register and a document card are enough.

## Forbidden Research Shortcuts

- do not create kinship solely from a matching patronymic;
- do not merge people with the same name;
- do not carry over a date or place from someone else's tree without a photocopy;
- do not treat a FamilySearch index as a photocopy;
- do not add living people without a separate decision to publish.
